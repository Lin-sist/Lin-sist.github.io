这份路线按业务模块组织 Redis 相关知识，方便安排学习顺序。每个阶段仍需要自己的代码、运行和复述来检验，路线本身不表示掌握程度。

Redis 知识点学习路线（按模块顺序）

第一阶段：基础 - 登录与 Session 替换

核心问题： 传统 Session 无法在集群间共享

涉及文件：

  • LoginInterceptor.java — 登录校验拦截器
  • RefreshTokenInterceptor.java — Token 刷新拦截器
  • UserServiceImpl.java — 登录逻辑

Redis 知识点：

  • String 类型存储验证码（带 TTL）
  • Hash 类型存储用户信息
  • Token 作为 key，实现无状态登录
  • 双拦截器设计：一个刷新 TTL，一个校验登录

第二阶段：缓存 - 商铺查询优化

核心问题： 缓存穿透、缓存雪崩、缓存击穿

涉及文件：

  • ShopServiceImpl.java — 三种缓存问题的解决方案
  • CacheClient.java — 封装的通用缓存工具类
  • RedisData.java — 逻辑过期数据封装

Redis 知识点：

问题 解决方案 Redis 用法
缓存穿透 缓存空值 set key ""
缓存雪崩 TTL 加随机值 expire 随机化
缓存击穿 互斥锁 / 逻辑过期 setnx 实现锁

第三阶段：全局 ID 与秒杀

核心问题： 高并发下的超卖、一人一单

涉及文件：

  • RedisIdWorker.java — 全局唯一 ID 生成
  • VoucherOrderServiceImpl.java — 秒杀核心逻辑
  • seckill.lua — 原子性库存扣减脚本

Redis 知识点：

  • incr 实现自增 ID（时间戳 + 序列号）
  • String 存储库存，set 存储已购用户
  • Lua 脚本保证原子性（判断库存 + 扣减 + 记录用户）
  • Redis Stream 消息队列异步处理订单

第四阶段：分布式锁

核心问题： 单机锁在集群环境下失效

涉及文件：

  • SimpleRedisLock.java — 手写 Redis 分布式锁
  • unlock.lua — 原子性释放锁脚本
  • RedissonConfig.java — Redisson 配置

Redis 知识点：

  • set key value nx ex 实现加锁
  • UUID 作为锁标识防止误删
  • Lua 脚本原子性释放锁
  • Redisson 的 WatchDog 机制（锁续期）

第五阶段：点赞与排行榜

涉及文件：

  • BlogServiceImpl.java

Redis 知识点：

  • ZSet 存储点赞用户（score = 时间戳，实现按时间排序的 Top5）
  • ZSet vs Set：需要排序时用 ZSet

第六阶段：关注与 Feed 流

涉及文件：

  • FollowServiceImpl.java
  • BlogServiceImpl.java — 推送逻辑

Redis 知识点：

  • Set 的 intersect 求共同关注
  • ZSet 实现 Feed 流（推模式/Push）
  • 基于 ZSet score 的滚动分页（不用 offset，用 lastId）

第七阶段：附近商铺

涉及文件：

  • ShopServiceImpl.java — queryShopByType 方法

Redis 知识点：

  • GEO 数据结构存储经纬度
  • GEOSEARCH 按距离范围查询
  • 结合分页返回附近商铺

第八阶段：UV 统计与签到

涉及文件：

  • UserServiceImpl.java — 签到方法

Redis 知识点：

  • BitMap 实现签到（每天一个 bit，极省空间）
  • BITCOUNT 统计连续签到天数
  • HyperLogLog 统计 UV（允许误差的海量数据统计）

推荐学习顺序

编码路线图

模块 1：短信登录（基础，必须先做）

理解 Redis 替代 Session 的核心思路

  1. 发送验证码 → 存入 Redis（String + TTL）
  2. 登录校验 → 用户信息存 Redis Hash，返回 Token
  3. 写 RefreshTokenInterceptor — 刷新 Token 有效期
  4. 写 LoginInterceptor — 校验登录状态
  5. 在 MvcConfig 注册两个拦截器，注意顺序

模块 2：商铺查询缓存（缓存三大问题）

这是 Redis 缓存的核心，要吃透

  1. 基础缓存：查询时先查 Redis，miss 再查 DB 并写入
  2. 解决缓存穿透：缓存空值
  3. 解决缓存击穿（互斥锁方案）：用 setnx 手写锁
  4. 解决缓存击穿（逻辑过期方案）：RedisData 封装 + 异步重建
  5. 将上述逻辑封装进 CacheClient 工具类（泛型 + 函数式接口）

模块 3：全局 ID + 秒杀下单

高并发核心，难点在原子性

  1. 写 RedisIdWorker — 基于 incr 生成全局唯一 ID
  2. 实现秒杀基础逻辑（查库存 → 扣减 → 创建订单）
  3. 加一人一单校验（注意事务 + 锁的范围）
  4. 发现单机锁在集群下失效 → 引出下一模块

模块 4：分布式锁

从手写到框架，理解演进过程

  1. 写 SimpleRedisLock — set nx ex 加锁，UUID 防误删
  2. 写 unlock.lua — Lua 脚本原子性释放锁
  3. 发现手写锁的缺陷（不可重入、无续期）→ 引入 Redisson
  4. 配置 RedissonConfig，用 Redisson 替换手写锁

模块 5：秒杀优化（异步下单）

将同步流程改为异步，提升吞吐量

  1. 写 seckill.lua — 原子判断资格（库存 + 一人一单）
  2. 用 Redis Stream 创建消息队列
  3. 主线程只做资格校验，异步线程消费队列创建订单

模块 6：点赞与排行榜

ZSet 的典型应用

  1. 点赞/取消点赞 — 用 ZSet 存储（score = 时间戳）
  2. 查询 Top5 点赞用户 — ZRANGE 按 score 排序

模块 7：关注 + Feed 流

Set 求交集 + ZSet 滚动分页

  1. 关注/取关 — 写入 Set
  2. 共同关注 — Set 的 intersect
  3. 发布笔记时推送给粉丝 — 写入粉丝的 ZSet 收件箱
  4. 实现滚动分页拉取 — 用 ZRANGEBYSCORE + lastId（不用 offset）

模块 8：附近商铺

GEO 地理位置

  1. 数据导入 — 按 typeId 分组，批量写入 GEO
  2. 查询附近商铺 — GEOSEARCH + 手动分页

模块 9：签到 + UV 统计

BitMap 和 HyperLogLog

  1. 签到 — SETBIT，key 按月份区分
  2. 统计连续签到天数 — BITFIELD 获取本月数据，位运算统计
  3. UV 统计 — HyperLogLog 的 pfadd / pfcount

关键原则

  • 模块 1-2 是基础，后面所有模块都依赖登录态，必须先完成
  • 模块 3-5 是一个整体，建议连续做完
  • 模块 6-9 相互独立，可以按兴趣调整顺序
这一段思考，先记到这里。
